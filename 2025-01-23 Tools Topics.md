The third and final I might write about for computational tools is all about embeddings and the overall process of a RAG application. First, RAG stands for Retrieval Augmented Generation, which I like to joke about as a fancy chatgpt wrapper. Essentially what a RAG application does is it has a dataset of documents / sections of a text book etc, which is used to find the most relevant info for the users query. Take for example, a RAG application which has access to every wikipedia page (this in actuality would probably be too large to work with but this is just an example). If a user asks the AI a question to the RAG application about Barack Obama. The RAG application would then look for the wikipedia page about Barack Obama, then give it to an AI telling it to use the information in the wikipedia page to answer the user's question. Now what role do embeddings play in this? In this case, embeddings are the vectorized form of strings. Essentially, we are converting a string into a vector (like those in geometry / math) so that way the 2 closest vectors represent two similar strings. For example, "dogs" and "puppies" might be similar vectors, and "cat" might be slightly further away than them but still somewhat close. Whereas "dynamite" would probably not be similar vectors.
